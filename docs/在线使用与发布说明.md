# TripFlow 在线使用与发布说明

适用版本：1.1.0。项目工作目录：`D:\trip flow`。

## 从个人主页进入

已于 2026-10-11 完成主页与应用发布，正式地址和保存刷新已经验收。打开 https://theoryofthewest.github.io/ ，点击顶部 TripFlow 或下方「打开 TripFlow」。直接地址是 https://theoryofthewest.github.io/tripflow/ 。日常使用不需要启动电脑上的开发服务，也不需要安装 GitHub Desktop 或 Node.js。

未配置云端服务时，网页直接进入旅行列表，不显示登录入口。新增旅行、记录交通、添加照片、查看时间线、导出和导入均在网页完成。具体按钮见《用户使用说明书》。

## 网页在线与数据在线的区别

当前网页由 GitHub Pages 在线提供；行程与照片保存在访问它的当前浏览器 IndexedDB 中。使用同一浏览器再次打开同一个正式地址，可以读取以前保存的记录和照片。不要清理此网站的站点数据，也不要用无痕窗口长期保存；浏览器容量限制和设备故障仍可能导致丢失，请定期导出完整 ZIP。

**目前没有跨电脑、手机自动同步，也没有云端文件库。** GitHub Pages 只能托管静态资源，不能接收网页里新增加的私人行程和照片。仓库上传只包含代码与说明，不包含旅行数据库。公开源码授权不代表公开私人旅行。

照片支持 JPG、PNG、WebP；可导入完整备份 ZIP、JSON 与指定格式的 GeoJSON 轨迹。任意 PDF、票据及其他附件的私人在线文件柜尚未实现。1.0.3 已接入 Geoapify，支持真实底图、在线地点搜索和道路步行估算；服务失败仍可手动输入坐标并使用明确标注的直线粗估。

若希望电脑和手机都直接读取同一份私人数据，即使没有传统登录页面，也需要身份或设备授权机制和后端存储；不能把管理员密钥放进网页，或让任何访问者都拥有写入私人空间的权限。此部分需另行确定同步与授权方式并配置服务，不能靠开启 Pages 达成。

## 完成一段旅程，下载留存并在本地查看

进入旅程 → 点击“保存旅程到电脑” → 核对信息 → “确认保存并下载”。ZIP 只包含这一整段旅程的已保存记录和真实照片。

- 离线阅读：解压整个 ZIP，双击“旅程回顾.html”，保留同目录 photos 文件夹；不需要登录或启动服务器，断网也可阅读照片与记录。
- 本地继续编辑：双击 D 盘项目的“启动TripFlow.cmd”，在本地首页点击“导入旅程”，选择原 ZIP，确认导入为新旅行。首次导入后，同一浏览器访问同一本地地址可直接查看。
- 收藏包需 1.1.0+ 导入；原有 JSON / ZIP 备份仍兼容。导入不会覆盖或合并原旅行，重复导入会产生副本；后续修改后请重新下载最新快照。

文件由浏览器下载至你设置的目录或提示选择位置。页面能确认已生成并发起下载，实际落盘请查看浏览器下载列表。该功能不改变云端状态，也不自动把下载文件上传 GitHub。

## 把以前本地开发地址的记录带过来

1. 在原浏览器打开原地址 `http://127.0.0.1:5173/tripflow/`；如服务已关闭，从 D 盘双击启动脚本。
2. 在「备份与导出」下载完整 ZIP，确保照片也已包含。
3. 在同一或目标浏览器打开正式在线地址，导入该 ZIP，确认导入为新旅行。
4. 检查旧行程和照片。导入不会覆盖原记录；重复导入会形成副本。

迁移源码目录不会移动浏览器数据；正式域名与本地开发来源的存储互相独立。在线版本升级继续使用相同来源和数据库，不要求用户反复迁移。

## 每次改进怎样同步

源码仓库：https://github.com/TheoryOfTheWest/tripflow 。发布仓库：https://github.com/TheoryOfTheWest/TheoryOfTheWest.github.io 。两者本机位置分别为 `D:\trip flow` 与 `D:\trip flow\work\personal-site`。

1. 在源码仓库获取远端更新，完成修改、适当测试、更新 CHANGELOG，然后提交并推送。
2. 从源码根目录执行 `npm run stage:site`。它重新构建、验证子路径，只把 dist 中的网页资源复制到个人网站仓库的 `tripflow/`，并记录 `release.json`。
3. 在 GitHub Desktop 添加或选择个人网站仓库，检查 Changes，然后提交，说明本次部署的 TripFlow 版本及源码提交，点击 Push origin。
4. 推送后可简短确认个人网站原有 Pages 构建状态。按照 2026-10-12 用户约定，默认跳过正式网站的交互、真实 API、下载/恢复等在线功能验收，不为此长时间等待或重试；只有用户明确要求才做。必要时由用户刷新页面使用新版本，不清理站点数据。

源码 push 成功与网站发布成功是两个独立状态；只上传源码不会自动更新挂载目录。源码 Actions 默认测试并保存构建产物；独立仓库 Pages 发布仅作为显式启用的替代方案。

首次挂载还会提交主页导航和工具卡片。后续只更新 `tripflow/` 内容，保留个人主页已有内容。脚本保留旧的带哈希资源，以便已打开的标签页在更新期间仍可加载；定期清理旧资源需单独检查引用。

所有说明文档随源码仓库同步；每次具体改进可在 GitHub Desktop History / GitHub Commits 中查看，版本摘要见 CHANGELOG。
## 地图配置更新

本机地图 Key 放在 D:\trip flow\.env 的 VITE_GEOAPIFY_API_KEY 中，不提交这个文件。浏览器 Key 会出现在发布后的网页资源中，应在 Geoapify 控制台限制正式网站来源，并按需允许本地开发来源。后续更新 Key 后执行原有 stage:site 和个人网站推送流程即可；源码 CI 默认没有本机 .env，不能把 CI 产物无配置地覆盖正式挂载版本。
