# TripFlow 用户使用说明书

适用版本：1.2.0 · 文档日期：2026-10-12

在线入口与当前保存方式见 [在线使用与发布说明](在线使用与发布说明.md)。未配置云端服务时不显示登录入口，直接使用浏览器保存。

本电脑项目位置：`D:\trip flow`。1.0.1 完成目录迁移与版本管理；1.0.2 增加个人主页挂载发布和无账户服务时的直接使用入口。启动、GitHub Desktop 同步及版本记录见 [运行部署与版本管理](运行部署与版本管理.md)。

TripFlow 用来记录一次旅行中“什么时候、在哪里、做了什么、怎样到达下一站”。主要操作都在每日时间线上完成，需要选地点或看路线时再打开地图。

本说明按当前项目的实际界面编写。网站地址、账户和在线地图是否可用，取决于网站维护者的配置。

## 1. 第一次使用：先完成一段小记录

1. 打开 TripFlow 网站，查看右上角的数据状态。
2. 点击“开启一段旅程”“新建旅行”或“创建我的第一段旅行”。
3. 填写旅行名称、出发日期、结束日期和旅行默认时区，点击“保存旅行”。
4. 在首页点击刚创建的旅行卡片，进入每日时间线。
5. 选择日期，点击“添加第一条记录”或“记录下一段时光”。
6. 选择“地点停留”，填写时间，通过“地图选点”确定地点，点击“保存记录”。
7. 回到时间线，确认名称、时间和地点正确。刷新页面，已保存的记录应仍然存在。
8. 一段旅程记录完成后，在旅程标题旁点击“保存旅程到电脑”→“确认保存并下载”，保存独立 ZIP 文件。

新安装的项目默认没有旅行数据。本地模式的空首页可以点击“先看看虚构三日示例”体验操作；示例会作为一段旅行保存，里面的行程、班次和示意照片都是虚构内容，可正常编辑或删除。

## 2. 先确认数据保存在哪里

| 页面状态    | 数据保存位置                                 | 可以做什么                           | 使用时注意                                         |
| ----------- | -------------------------------------------- | ------------------------------------ | -------------------------------------------------- |
| 本地模式    | 当前浏览器的站点存储                         | 创建、编辑、删除、备份和导入         | 不会自动出现在另一台设备上；清理站点数据会丢失记录 |
| 云端已连接  | 当前登录账户的云端空间，同时保留部分本地缓存 | 联网读写，其他设备登录同一账户后读取 | 另一设备修改后需要刷新；没有实时自动合并           |
| 离线 / 缓存 | 当前设备已缓存的云端内容                     | 查看已有缓存、导出能够读取的数据     | 云端编辑和导入停用，未缓存的照片可能无法显示或导出 |

“云端已连接”表示已登录且当前没有进入缓存只读状态；每次保存是否成功仍以该次操作结果为准。

本地数据按网站来源保存。`127.0.0.1` 与 `localhost`、不同端口、正式网站地址使用不同的存储空间；换地址后列表为空，不一定是原数据被删除。应回到原地址导出备份，再到新地址导入。

已经打开的页面在断网后，本地记录仍可编辑；在线地点搜索、真实地图和道路路线需要网络。当前版本没有保证断网后首次打开或重新加载整个网站的离线安装功能。

## 3. 创建、查找和编辑旅行

### 3.1 创建旅行

新建窗口中填写：

- **旅行名称**：例如“京都的三个清晨”，最多 150 个字符。
- **出发日期、结束日期**：包括首尾日期，最长 366 天。
- **旅行默认时区**：决定每天如何划分。中国通常填写 `Asia/Shanghai`，日本填写 `Asia/Tokyo`，英国填写 `Europe/London`。
- **旅行备注**：可记录整体安排或想法。
- **封面风格**：山间、海岸、城市、森林。

填写时区请使用上述地区形式，不要填写“北京时间”“日本时间”或自行拼写的时差。

点击“保存旅行”后，窗口关闭；再点击首页对应卡片进入旅行。首页的“寻找一段旅程”可以按旅行名称或旅行备注查找。

### 3.2 修改旅行与封面

进入旅行后，点击标题附近的铅笔按钮“编辑旅行”。已经保存过照片的旅行，可以在“或使用旅行照片作为封面”中选择照片；选择“使用插画封面”可切回插画。

调整日期不能把已有记录排除在旅行范围之外。如果需要记录更早或更晚的活动，先扩展旅行日期，再添加记录。改变默认时区可能改变记录归属的日期，请保存后检查每日视图。

## 4. 阅读每日时间线

页面上方的 DAY 日期标签、“上一天”“下一天”和日期选择器，都可以切换日期。前一天最后一条、后一天第一条的衔接提示，也能帮助你继续查看。

时间线按实际发生的先后顺序自动排列，修改记录时间后会重新排序，无需手动拖动。

| 时间线内容                | 含义                                               |
| ------------------------- | -------------------------------------------------- |
| 地点停留卡片              | 游览、美食、住宿、购物、休息等有起止时间的活动     |
| 交通移动卡片              | 从起点到终点的一段移动及其交通信息                 |
| 照片 / 备注记录           | 某个时间点的独立随记，可以没有地点                 |
| 未记录时段                | 相邻已知记录之间的空白；不代表系统知道你当时在休息 |
| 时间重叠提示              | 两条记录的时间有交集；允许保存，请确认是否符合实际 |
| 承接前一天 / 延续至后一天 | 同一条记录跨越日界，在相关日期分段显示             |

每日卡片主要使用**旅行默认时区**显示时间；有异时区信息时还会展示相关当地时间。午夜结束可能显示为 `24:00`。

跨天卡片的当日时间和时长只对应当天部分，“全程”对应整条记录。旅行概览只保存和统计这条原记录一次。重叠活动各自计时，因此“记录时长合计”可能大于实际经过的时间。

空白处的加号也能打开新增记录窗口，但当前不会自动把该空白时段完整填入表单。无论从哪个入口新增，都要核对开始与结束时间。

## 5. 添加地点停留

1. 进入对应日期，点击新增记录按钮。
2. 选择“地点停留”。
3. 填写“活动名称”。留空时系统会根据所选地点生成名称。
4. 填写开始、结束的完整日期和时间，核对“开始时区”“结束时区”。
5. 在“活动地点”选择已有地点，或点击“地图选点”添加地点。
6. 选择活动类型：游览、美食、住宿、购物、休息或其他。
7. 按需填写备注、添加照片。
8. 点击“保存记录”，回到时间线核对结果。

### 5.1 地图选点的三种方法

1.0.3 个人网站版本已接入在线地图服务，可以直接使用真实底图、地点搜索和道路步行估算。无需在网页内自行填写 Key。

**搜索地点**：在地图窗口输入至少两个字符，可选择中文、English 或日本語。点击搜索结果后，核对名称、地址和位置，再点击“确认地点”。在线搜索需要网站已配置地图服务。

**复用地点**：在记录表单选择本旅行已有地点；地图窗口还会提供当前数据范围内的已保存地点历史，便于复用以前旅行去过的位置。

**手动选点**：点击地图确定坐标，或填写地点名称、地址、纬度、经度和地点类型，再点击“确认地点”。纬度范围为 -90～90，经度为 -180～180，不要填反。

没有配置 Geoapify 时，窗口显示的是坐标网格，仍可手动输入坐标，但它不是实际街道地图，不能依靠网格辨认建筑位置。

“确认地点”会将地点带回记录表单；还需要点击“保存记录”，这条记录及新地点才会一起保存。

### 5.2 记录跨午夜活动

例如住宿或夜间交通：

| 字段           | 示例             |
| -------------- | ---------------- |
| 开始时间       | 2026-10-16 22:00 |
| 结束时间       | 2026-10-17 06:00 |
| 开始、结束时区 | Asia/Shanghai    |

实际时长为 8 小时。填写一条完整记录即可，不要为了分到两天而重复创建两条。

## 6. 添加交通移动

选择“交通移动”，填写出发与到达时间、各自时区、交通方式和两端地点。

支持步行、地铁、铁路、公交、自行车、汽车 / 出租车、飞机、轮渡和其他。地铁、铁路、公交使用“上车站”“下车站”；其他方式使用“起点”“终点”。站点名称可以复用，也可以通过地图新增。

根据交通方式，表单会提供“线路 / 班次”、运营商、换乘信息等字段。线路可手动填写，已有线路会进入输入历史；历史下拉的样式由浏览器决定。

本版不会查询官方时刻表、票价或实时班次。多次换乘建议拆成多条交通记录，例如“地铁 A 线”“站内换乘”“地铁 B 线”，分别填写实际起止时间。

### 6.1 跨时区行程

按每一端的当地时间填写，并为两端分别选择时区。例如下面仅用于说明填写方式，不是真实航班：

| 字段               | 示例                            |
| ------------------ | ------------------------------- |
| 出发时间、开始时区 | 2026-10-18 10:00，Asia/Tokyo    |
| 到达时间、结束时区 | 2026-10-18 11:00，Asia/Shanghai |

这段行程实际经过 2 小时，而不是当地钟点相减得到的 1 小时。系统按真实时间排序和计算。

遇到采用夏令时的地区，某些当地钟点可能不存在，或同一钟点发生两次。不存在的时间需要修改；重复时间需要根据真实行程选择表单提示的 UTC 偏移。

### 6.2 计算步行

1. 选择“步行”，确定起点和终点。
2. 按需要调整步行速度，默认 4.5 km/h，可填 1～10 km/h。
3. 点击“计算步行”。不会在你每次输入时自动请求路线。
4. 查看估计距离、耗时和来源说明。
5. 自己填写实际到达时间，再保存记录。

服务可用时显示道路路线估计；未配置、超时或失败时会显示“直线粗估（精度有限）”。直线粗估没有考虑道路、坡度、障碍和绕行，不能当作导航结果。

步行速度设置用于直线粗估；在线道路结果的耗时由 Geoapify 返回，当前不会按你填写的速度重新计算。

**计算结果不会自动替你填写到达时间。** “估计耗时”与根据起止时间计算的“实际耗时”分别保存；修改起终点、方式或速度后，应重新核对估计。

### 6.3 导入自己的 GPS 轨迹

展开“导入此路段实际 GPS 轨迹（可选）”，选择 `.geojson` 或 `.json` 文件。当前支持 WGS84 的 GeoJSON `LineString` / `MultiLineString`，可以是几何对象或 Feature，文件不超过 2 MB，坐标顺序为 `[经度, 纬度]`。

应导入属于当前交通路段的实际轨迹。GPX 文件暂不支持，需要先转换。导入轨迹不会自动推算实际到达时间，也不会自动根据轨迹计算距离和耗时。

## 7. 照片与独立随记

### 7.1 先用照片填写开始与结束节点（1.2.0）

1. 新增或编辑记录，在表单前面的“用照片锚定这段时光”选择 **开始锚定照片**。
2. 有拍摄时间就预填开始时间，有 GPS 就预填开始地点；只提取到其中一项，也能单独填写这一项。
3. 按需选择 **结束锚定照片**，同样预填结束时间与结束地点。地点停留会显示“结束地点（可选）”，交通记录对应起点与终点。
4. 查看每张锚定照片下方的解析结果，核对时间、时区和地点；任何字段仍可手动修改。填写活动名称、备注及其他附件后，点击 **保存记录**。

照片带时区偏移时，会换算到对应节点当前填写的时区；没有偏移时，暂按表单当前时区解释拍摄钟点，请核对。GPS 只提供坐标，显示“开始照片地点 / 结束照片地点”，不自动猜测景点名称；可通过地图修改名称或位置。自动填入的时间保留秒。若照片日期超出旅行日期，请先扩展旅行日期再保存。

没有有效拍摄时间或 GPS 时，会明确提示，对应字段保留原值。不要把文件名或下载时间当作拍摄时间；聊天软件、截图及转换图片可能已移除信息，尽量使用原图。照片格式仍限 JPG / PNG / WebP，HEIC 需先转换并保留所需元数据。

每条记录的开始、结束锚定照片各最多一张；重新选择会将旧锚定照片保留为普通附件。删除锚定照片不会撤销已经预填的字段。“照片 / 备注”是单个时间点，只提供开始锚定入口；从其他类型切换为单个时间点时，结束照片保留为普通附件。

解析在本机浏览器完成，不调用地图 API，也不上传原图来识别地点。照片仍作为记录中的附件保存，与普通附件合计最多 12 张；压缩后的图片去除原始 EXIF / GPS，已确认的节点时间、地点及锚定标记单独保存。刷新、完整 ZIP 备份和恢复后保留这些信息；建议使用 1.2.0 或更新版恢复，以完整保留新增字段。

### 7.2 给活动或交通添加普通附件照片

在新增或编辑记录窗口下方点击“添加照片”选择普通附件，可多选、填写图片说明，也可以移除待保存照片。点击“保存记录”后，照片和记录一起保存；只选择文件并不代表已经上传或保存。

- 支持 JPG、PNG、WebP；HEIC 请先转换。
- 单张原图不超过 20 MB，每条记录最多 12 张。
- 系统将图片压缩到最长边 1800px，并重编码去除 EXIF / GPS 元数据。
- 日常上传会转换成 JPEG；透明部分会使用白色背景。
- 网站保存的是压缩版本，原始高清照片请另行保管。

在时间线点击缩略图可打开大图。修改说明或删除照片时，打开所属记录的编辑窗口，修改后点击“保存记录”。删除正在用作封面的照片，会让旅行回到插画封面。

### 7.3 只记一张照片或一句话

新增记录时选择“照片 / 备注”，填写发生时间、时区、标题或备注，按需关联地点和照片。它是一个时间点，没有结束时间，不占用一段活动时长。

只有通过“开始锚定照片”明确选择的照片会解析拍摄信息；下方“添加照片”只添加普通附件，不解析、不改写节点。保存时，普通新附件的时间沿用记录开始时间，结束锚定照片关联最终确认的结束时间。

## 8. 查看地图与旅行概览

- 点击记录中的地点名称或地图按钮：查看该地点位置。
- 点击“查看今日路线”：查看当前日期的地点顺序和相关路段。
- 点击“旅行概览”→“整段旅行地图”：查看整段旅行的路线。
- 点击路线编号点，在有对应记录的弹出信息中选择返回时间线，可回到相应日期和记录。

| 地图线条 | 表示什么                                 |
| -------- | ---------------------------------------- |
| 棕色虚线 | 地点之间的时间顺序示意，不是真实行驶路径 |
| 绿色实线 | Geoapify 返回的道路路线                  |
| 紫色实线 | 用户导入的 GPS 轨迹                      |

交通站点使用方形标记。连续路段共用的同一端点可能合并为一个编号；时间线中的原记录仍然分别保留。没有地点的独立随记不会生成地图点。

跨天交通在每日地图中显示的是**整条路段的几何轨迹**，当前没有按午夜切开轨迹。没有在线地图配置时，仍可能看到网格上的编号点和示意线。

## 9. 备份、恢复与换设备

### 9.0 一段旅程完成后，保存到电脑

1. 先保存正在编辑的旅行或记录，回到该旅程的时间线。
2. 点击标题旁的 **“保存旅程到电脑”**。手机上也显示此按钮。
3. 核对旅行名称、日期、记录数和照片数，点击 **“确认保存并下载”**。
4. 等待生成，在浏览器下载列表确认 ZIP 下载完成。文件名带有旅行名称、旅行日期和保存时间；下载目录或“另存为”窗口由浏览器设置决定。
5. 后续修改记录后，再次点击保存下载，得到新的文件快照。

此按钮只归档**当前这一整段旅程，包含所有日期**；不会把其他旅行混进去，也不会删除或锁定浏览器中的原旅行。归档包括记录、备注、地点、交通、已存道路/GPS几何、照片说明和网站中的实际照片文件（压缩版本）。缺少任何照片时会明确报错，请补齐后重试。

**直接离线阅读**：解压整个 ZIP，双击其中的 `旅程回顾.html`，可以断网查看文字、时间顺序和照片。请保留旁边的 `photos` 文件夹，移动收藏时一起移动整个解压目录。此图文回顾没有在线地图底图；路线数据仍保存在可恢复的 JSON 中。单独的 HTML 用于阅读，恢复时要使用原 ZIP。

**下次在本地继续查看和编辑**：双击 `D:\trip flow\启动TripFlow.cmd`，打开本地版 TripFlow → 首页 **“导入旅程”** → 选择刚下载的原 ZIP → 核对名称 → **“确认导入为新旅行”**。然后打开旅行卡片，记录和照片已恢复。后续使用同一浏览器、同一本地地址即可直接访问已导入内容，无需每次导入。正式网站也能导入这个文件。

收藏包需要 TripFlow **1.1.0 或更新版**导入。它保留原来的 v1 数据结构；旧 JSON/完整 ZIP 备份仍能导入。重复导入会创建副本，不会覆盖原旅行。浏览器无法自动读取你电脑上未选择的文件，因此首次恢复需要上述导入操作。

首页顶部“备份与导出”仍可打开备份窗口；手机页面有单独的同名入口。这里的 JSON / 完整 ZIP 导出范围是**当前模式 / 账户下已经加载的全部旅行**。只保存某一段旅行时使用旅程内的新按钮。

### 9.1 选择哪种文件

| 文件            | 包含内容                                             | 适合用途                             |
| --------------- | ---------------------------------------------------- | ------------------------------------ |
| 单旅程收藏 ZIP  | 当前旅程数据、实际照片、离线图文回顾和说明           | 旅程完成归档、离线阅读、本地继续编辑 |
| JSON 数据备份   | 旅行、地点、记录、路线、照片说明及引用；没有照片文件 | 轻量备份文字与结构，供程序分析       |
| 完整 ZIP 备份   | JSON 与每张实际照片文件                              | 正式归档、换设备、从本地迁移到云端   |
| HTML 报告 / PDF | 便于阅读的单段旅行记录                               | 阅读、打印；不能当作可恢复的数据备份 |

导出文件通常为 `tripflow-backup.json` 或 `tripflow-full-backup.zip`。浏览器可能在重名文件后自动加序号，建议自己加上备份日期，妥善保存。

完整 ZIP 会逐张读取实际图片；任何照片缺失都会报错，不会生成声称完整但缺图的 ZIP。云端缓存不全时，请联网后再导出。导出的备份是普通文件，里面包含私人行程和照片，应自行保管。

### 9.2 导入备份

1. 确认当前处于要恢复到的本地模式或云端账户。
2. 点击首页“导入旅程”，或“备份与导出”→“导入 JSON 或 ZIP”。
3. 选择文件，等待显示校验后的旅行数和照片数。
4. 点击“确认导入为新旅行”，处理期间保持窗口打开。
5. 返回首页检查新旅行，打开记录和照片确认恢复结果。

导入会生成新的旅行和记录，**不会覆盖或合并原旅行**。重复导入会产生副本。JSON 导入只能恢复图片引用，图片会标记为需要 ZIP 恢复；后来导入完整 ZIP 也会创建另一段完整的新旅行，不会自动给旧副本补图。

一次导入文件上限为 100 MB，ZIP 解压后上限为 200 MB、最多 5001 个数据/照片文件（单旅程收藏包额外允许 2 个阅读辅助文件），备份内单张照片上限为 8 MB。如果文件超过限制，请保留原备份并联系维护者处理；当前界面没有自动拆分大备份的功能。

多旅行导入按旅行依次保存，中途失败可能已经成功导入一部分。按提示刷新核对结果，再决定是否重试，避免重复导入已经成功的部分。

### 9.3 从本地迁移到云端

1. 在本地模式导出完整 ZIP，确认文件已下载。
2. 登录已配置好的个人云端账户。
3. 导入刚才的 ZIP，确认导入为新旅行。
4. 在另一设备打开同一个网站，登录同一账户并刷新，核对记录和照片。

登录不会自动上传本地旅行；退出云端后会重新显示本地模式的数据，因此两边的列表可能不同。

## 10. 导出报告和 PDF

进入一段旅行，点击“旅行概览”：

- 选择“HTML 报告”，下载 `tripflow-report.html`，可用浏览器打开阅读。
- 选择“打印 / PDF”，在浏览器打印窗口中选择打印机或“另存为 PDF”。手机的保存入口由系统和浏览器决定。

报告包含按实际时间排列的记录。HTML 会列出关联照片数量，但不嵌入照片文件；打印概览也不提供完整照片相册。两者都没有地图截图。保存完整图片请使用 ZIP。

## 11. 编辑、删除与保存失败

记录卡片的铅笔按钮用于编辑，垃圾桶按钮用于删除。旅行标题旁的垃圾桶用于删除整段旅行。删除需要点击“确认删除”，会同时移除相关照片；当前没有回收站和撤销功能，重要内容先导出完整 ZIP。

**输入并不等于保存。** 必须点击“保存旅行”或“保存记录”，并等到成功返回。当前没有未提交表单的自动草稿恢复；关闭窗口或刷新页面会丢失未保存的输入。

| 遇到的问题                             | 操作方法                                                                 |
| -------------------------------------- | ------------------------------------------------------------------------ |
| 提示未保存或网络异常，编辑窗口仍在     | 保持窗口，恢复联网后重试；必要时先复制备注并记下时间、地点等输入         |
| 提示另一设备 / 窗口已修改旅行          | 先保留自己未保存的内容，再关闭编辑、刷新，基于最新记录重新编辑           |
| 提示保存结果需刷新核对、已上传照片保留 | 先保留未保存输入，再刷新确认记录是否已保存，避免直接新增重复记录         |
| 显示“离线 / 缓存”，编辑按钮不可用      | 联网后保留好未提交内容，再刷新重新读取云端；仅恢复网络不保证自动重新读取 |
| 地点搜索不可用或只有网格               | 可手动输入准确坐标；在线地图配置交由维护者检查                           |
| 图片提示需 ZIP 恢复                    | 可能只导入了 JSON；用完整 ZIP 导入新的完整旅行，再核对并清理不需要的副本 |
| ZIP 导出提示缺照片                     | 联网重试并核对图片；只有 JSON 无法还原实际照片                           |
| 删除后提示图片清理失败                 | 记录可能已经删除；交由维护者核对私有存储中的具体文件，不必重复删除旅行   |
| 登录后找不到刚才的旅行                 | 检查本地 / 云端模式、登录账户与网站地址，数据不会自动跨模式迁移          |

共享设备使用完毕后，请主动退出云端账户。退出会清理该账户的本地缓存；浏览器缓存本身没有客户端磁盘加密。本地模式的数据不会因为退出云端而自动清除。
